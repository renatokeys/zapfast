Documentação da API zapfast

A API zapfast é REST/JSON e usa o mesmo contrato da Z-API, com a diferença que você controla o backend. Todas as rotas suportam HTTPS.

Base URL deste ambiente:

https://zapfast.5-161-161-140.nip.io

Instalação

Em qualquer VPS Linux, com Docker + Compose:

# clone
git clone https://github.com/renatokeys/zapfast
cd zapfast

# suba
cp .env.example .env
docker compose up -d

# sua API está em http://localhost:8080

Autenticação

Duas camadas de auth:

  • Admin token — header Authorization. Usado pra criar/listar/deletar instâncias.
  • Instance token — header Token. Usado para enviar mensagens e gerenciar sessão.
GET

/admin/users

Lista todas as instâncias do servidor.

curl ${endpoint}/admin/users \
  -H "Authorization: $ADMIN_TOKEN"
POST

/admin/users

Cria uma nova instância. Retorna ID e token da instância.

curl -X POST ${endpoint}/admin/users \
  -H "Authorization: $ADMIN_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "vendas-sp",
    "webhook": "https://meusite.com/webhook"
  }'
DELETE

/admin/users/{id}

Remove instância (irreversível).

POST

/session/connect

Inicia a sessão WhatsApp. Após esta chamada, peça o QR pra escanear no celular.

curl -X POST ${endpoint}/session/connect \
  -H "Token: $INSTANCE_TOKEN"
GET

/session/qr

Retorna o QR code (data URL base64) pra conectar o WhatsApp.

GET

/session/status

Verifica se a instância está conectada.

POST

/chat/send/text

Envia mensagem de texto simples.

curl -X POST ${endpoint}/chat/send/text \
  -H "Token: $INSTANCE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "Phone": "5511987654321",
    "Body": "Olá! Tudo bem?"
  }'
POST

/chat/send/image

Envia imagem (URL pública ou base64).

curl -X POST ${endpoint}/chat/send/image \
  -H "Token: $INSTANCE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "Phone": "5511987654321",
    "Image": "https://exemplo.com/imagem.jpg",
    "Caption": "Olha essa imagem!"
  }'

Webhooks

Configure a URL de webhook na criação da instância. Você receberá POSTs JSON para eventos:

  • Message — mensagem recebida
  • ReadReceipt — recibo de leitura
  • Presence — online/digitando
  • Connected/Disconnected — status conexão
